# Tarkov Search — Fabric mod (Minecraft 1.21.11)

Визуальный мод: когда игрок **первый раз** открывает сгенерированный лутом
сундук (или бочку/сундук эндера — любой `LootableContainerBlockEntity`),
предметы в нём на случайное время закрываются иконкой лупы, которая
исчезает по одному предмету в случайном порядке — как поиск предметов в
Escape from Tarkov. Генерация лута **не меняется вообще** — мод только
"подглядывает" за моментом её первого запуска и подменяет отрисовку в GUI.

## Как это работает

1. **Сервер** (`LootableContainerBlockEntityMixin`) отслеживает момент,
   когда ванильный код генерирует лут для сундука в первый раз (это уже
   штатное поведение майнкрафта — лут "катается" один раз при первом
   открытии). В этот момент мод узнаёт, какие слоты инвентаря оказались не
   пустыми, и отправляет игроку, который открыл сундук, пакет с позицией
   сундука и списком этих слотов.
2. **Клиент** (`RevealManager`) получает пакет и назначает каждому слоту
   свою случайную задержку (0.9–5.75 сек) до "проявления".
3. **Клиент** (`HandledScreenMixin`) при отрисовке GUI сундука подменяет
   иконку предмета на лупу для слотов, которые ещё скрыты, и блокирует их
   тултип. Как только время истекает — слот начинает рисоваться как обычно.

Сами предметы всё это время реально лежат в инвентаре: их можно доставать,
перекладывать, стакать — визуально скрыт только рендер иконки.

## Вариант A — собрать через GitHub Actions (не нужен Java/Gradle локально)

В проекте уже есть `.github/workflows/build.yml`. Достаточно:

1. Создать пустой репозиторий на GitHub.
2. Залить в него содержимое этой папки:
   ```bash
   cd tarkov-search-mod
   git init
   git add .
   git commit -m "Initial commit"
   git branch -M main
   git remote add origin https://github.com/<ваш-юзернейм>/<репозиторий>.git
   git push -u origin main
   ```
   (Или через веб-интерфейс GitHub: New repository → "uploading an existing
   file" → перетащить туда всю папку.)
3. Открыть вкладку **Actions** в репозитории на GitHub — сборка запустится
   автоматически при пуше (можно также нажать "Run workflow" вручную).
4. Дождаться зелёной галочки (обычно 3–7 минут — GitHub качает сам
   Minecraft/мэппинги/Fabric API на своих серверах).
5. Открыть завершённый workflow run → внизу страницы раздел **Artifacts** →
   скачать `tarkov-search-mod-jar.zip`. Внутри — готовый `tarkov-search-1.0.0.jar`.

Никакой Java, Gradle или IDE устанавливать не нужно — всё делает GitHub.
Единственное требование — аккаунт на GitHub (бесплатно), у бесплатных
аккаунтов есть лимит минут CI, но одной сборки мода на него хватит с
большим запасом.

## Вариант B — собрать локально

Нужны: JDK 21 и интернет (Gradle сам скачает Minecraft, мэппинги и Fabric
API при первой сборке).

В архиве **нет** обёртки `gradlew`/`gradlew.bat` (это бинарный файл
`gradle-wrapper.jar`, который нельзя просто написать текстом) — поэтому
для локальной сборки нужно один раз поставить Gradle самому:

1. Установите Gradle 8.14 (например через [SDKMAN](https://sdkman.io/):
   `sdk install gradle 8.14`, или скачайте с gradle.org).
2. В папке проекта выполните:
   ```bash
   gradle build
   ```
   Хотите — сразу сгенерируйте wrapper командой `gradle wrapper`, после
   чего дальше сможете пользоваться привычным `./gradlew build`.

Проще всего в IDE: откройте папку в **IntelliJ IDEA** — она сама предложит
импортировать Gradle-проект, скачает всё нужное и добавит wrapper
автоматически, тогда `./gradlew` заработает без ручной установки Gradle.

Готовый `.jar` появится в `build/libs/tarkov-search-1.0.0.jar` (там же
будет `-sources.jar`, его в `mods/` класть не нужно). Нужен ещё сам Fabric
Loader и Fabric API 0.141.2+1.21.11 в папке `mods/` вашего клиента/сервера.

## ⚠️ Важный момент про версию 1.21.11

1.21.11 — очень свежий релиз (вышел близко к границе моих актуальных
знаний), и Mojang/Fabric в этом релизе как раз переводят экосистему с Yarn
на официальные мэппинги Mojang. Я специально закрепил в `gradle.properties`
**Yarn 1.21.11+build.1** (она ещё существует и публикуется), чтобы код было
проще писать и читать — но это значит, что часть API, особенно рендеринг
(`DrawContext#drawTexture`), в последних снапшотах 1.21.x менялась несколько
раз. Я сверил актуальную сигнатуру для 1.21.11 прямо перед написанием кода,
но если после `./gradlew build` IDE подсветит именно эту строку в
`HandledScreenMixin` — это самое вероятное место, где придётся поправить
1-2 аргумента под автодополнение IDE (сама механика — сеть, таймеры,
mixin в LootableContainerBlockEntity — трогать не должно).

Если что-то не компилируется:
1. Откройте проект в IntelliJ IDEA (с плагином Minecraft Development — не
   обязателен, но удобен).
2. Дайте Gradle докачать зависимости — сгенерируется маппленный код
   Minecraft, и автодополнение IDE подскажет точные имена методов/полей.
3. Обычно "плывут" только сигнатуры рендер-методов (`DrawContext`) — сама
   логика (мьютексы, сеть, таймеры) от версии к версии почти не меняется.

## Настройка тайминга

В `RevealManager.java`:

```java
private static final int MIN_DELAY_MS = 900;   // мин. задержка проявления
private static final int MAX_DELAY_MS = 5500;  // макс. задержка
private static final int JITTER_MS = 250;       // доп. случайный разброс
```

Можно свободно менять под себя.

## Возможные доработки (не реализовано)

- Своя, более "тарковская" по стилю иконка лупы (сейчас — простой
  сгенерированный плейсхолдер 16×16, PNG, лежит в
  `assets/tarkovsearch/textures/gui/search_icon.png` — замените на свою
  текстуру того же размера).
- Звук/анимация вращения лупы.
- Не показывать эффект, если сундук уже "давно" стоит в мире (сейчас эффект
  срабатывает у любого игрока, который первым физически откроет сундук —
  это и есть момент броска лута, так что переигрывания не будет).
